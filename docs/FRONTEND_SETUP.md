# Frontend Setup

Setup and architecture for the Next.js application. For the product, the data
contract, and the database, see [`../README.md`](../README.md),
[`PRODUCT_SPEC.md`](PRODUCT_SPEC.md), and [`DATA_MODEL.md`](DATA_MODEL.md).

## Stack

| Concern | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router, React 19, TypeScript) |
| Styling | Tailwind CSS v4, CSS-first config with brand tokens |
| Type | Space Grotesk via `next/font/google` |
| Data | Contract-shaped fixtures behind `src/lib/repository.ts` |

No runtime dependencies beyond Next and React — the horizon artwork, the OI
monogram, and every icon are inline SVG or CSS, so there are no image requests
on any page.

## Data architecture

Three layers, and the boundary between them is enforced by convention that is
easy to check: **no page or component imports from `@/data/*`.**

```
data/opportunities.seed.json   canonical dataset, shared with supabase/seed.sql
src/data/*.ts                  contract-shaped fixture rows (snake_case)
        ↓  read only by
src/lib/repository.ts          the single data-access boundary
        ↓  returns
src/lib/types.ts               camelCase domain objects
        ↓  consumed by
src/app/**, src/components/**
```

- **`src/lib/contract.ts`** mirrors `supabase/schema.sql` exactly: snake_case
  fields, lowercase enum labels, flat `*_min` / `*_max` / `*_open_ended` ranges.
- **`src/lib/repository.ts`** is the only module allowed to read fixtures. It
  translates rows to domain objects once, applies filtering and sorting, and
  exposes async functions so Phase 2 can swap in Supabase without touching a
  single call site.
- **`src/lib/types.ts`** holds the camelCase domain types components consume.

Opportunities are read from `data/opportunities.seed.json` — the same file
`supabase/seed.sql` loads into the database — so the fixture and the seed cannot
drift.

### The score

`overall_score` is generated by the database and is never recomputed in the UI.
Until Phase 2 connects Postgres, `generatedOverallScore()` in the repository
stands in for the generated column. It is the **only** place in the application
permitted to evaluate the formula, it uses the published weights from
`scoring_factors` rather than hard-coded numbers, and it is deleted when the
database arrives.

## Design system

Brand tokens live at the top of `src/app/globals.css`:

| Token | Hex | Name |
| --- | --- | --- |
| `--color-space` | `#0D1117` | Space Black |
| `--color-slate-deep` | `#1A1F2B` | Deep Slate |
| `--color-horizon` | `#2563EB` | Horizon Blue |
| `--color-mist` | `#F5F7FA` | Light Gray |

Everything the UI paints goes through semantic variables (`--bg`, `--fg`,
`--border`, `--accent`, …) redefined under `.dark`. The theme is set on `<html>`
before first paint by an inline script, and `ThemeToggle` reads it with
`useSyncExternalStore` so the server render and the first client render agree.

## Routes

```
/                            Homepage — hero, category rail, ranked index
/hustles                     Full index with filters and sorting
/hustles/[slug]              Opportunity detail + score breakdown
/businesses                  Category overview
/businesses/[category]       Filtered index per category
/businesses-for-sale[/slug]  Acquisition listings
/franchises[/slug]           Franchise concepts
/funding[/slug]              Funding routes compared
/research[/slug]             Reports, guides, data studies
/tools                       Startup cost · break-even · compare
/about /methodology /advertise /contact /newsletter
/privacy /terms /disclaimer
```

Category routes use the contract's canonical slugs — `/businesses/ecommerce`
and `/businesses/local`. `next.config.ts` permanently redirects the
pre-contract spellings (`e-commerce`, `local-business`) so older links survive.

Filters, search, and sort are held in the URL and applied on the server, so any
filtered view is shareable, survives a refresh, and renders without JavaScript.
Query values use contract enum labels (`?flex=remote`, `?kind=data_study`);
capitalisation is applied for display only.

## Advertising

`AdSlot` renders labelled, correctly-sized placeholders at each IAB format
(728×90, 300×600, 300×250) so no layout shifts when real creative is dropped in.
Sponsored placements are visually distinct and labelled. No placement can affect
a score, a rank, or inclusion — stated on `/methodology` and true in the code:
no scoring input references advertising.

## Counts

Counts shown to readers are computed from the data, never hard-coded, so nothing
on screen claims more coverage than the index holds.
